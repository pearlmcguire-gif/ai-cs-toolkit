# QBR Prep Skill

## Purpose

Turn account data into a business review that centers the customer's outcomes, not a product usage report. Based on general industry-standard QBR structure, intended to be adapted to a real client's format and cadence.

## Structure

1. **Recap of goals set last QBR (or at onboarding, if this is the first one).** State them plainly. If a goal wasn't met, say so. Don't quietly drop it from the agenda.

2. **Value delivered this period.** Tie usage/adoption data directly to the stated goals, not a generic feature-usage summary. "You wanted to reduce manual reporting time; usage of the automated report feature is up 40% and covers 3 of your 4 target teams" is a value statement. "Logins are up 12%" is not, on its own.

3. **What's not working / open gaps.** Include this even when it's uncomfortable. A QBR that only shows green metrics reads as a sales pitch, not a business review, and erodes trust with sophisticated buyers.

4. **Roadmap alignment.** Only share roadmap items that are genuinely relevant to this account's stated goals, a generic roadmap slide doesn't build confidence, a targeted one does.

5. **Goals for next period.** Set 2–3 specific, measurable goals collaboratively in the meeting, not just for the record.

6. **Asks.** Anything the CSM needs from the customer (an internal champion, access to a stakeholder, a case study) and anything the customer has asked for that requires internal follow-up.

## Preparation Checklist

Before the meeting: confirm the right stakeholders are attending (not just the day-to-day contact if this is meant to be an executive review), pull current usage/health data, and identify at least one expansion or advocacy opportunity to raise if the account's health supports it. Don't force one if it doesn't.

## Output

A QBR outline or deck skeleton following the structure above, populated with the account's actual data. Never a placeholder metric presented as if it were real.
